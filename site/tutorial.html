Build a Pomodoro timer

The README gets you to a counter. Let's build something you'd actually leave running — and meet most of milktea on the way.

covers · constraint layouts · timers · styling · state & keys

Here's what we're making — a title bar, a stats sidebar, a centered timer panel with a live progress bar, and a status line. Everything is laid out with constraints, so it reflows when you resize the terminal.

Every milktea program is the same three things: a model (your state), an update function (react to events), and a view function (draw). We'll build each in turn. The full source is in examples/pomodoro/pomodoro.c3, and the long-form write-up lives in TUTORIAL.md.

1. The model

Your whole app, as one flat struct.

Keep state boring and explicit. Ours tracks the phase, seconds remaining, whether it's running, sessions completed, and the terminal size.

pomodoro.c3
enum Phase : int { FOCUS, BREAK }

struct Model {
    Phase phase;
    int   remaining;   // seconds left in this phase
    bool  running;
    int   completed;   // focus sessions finished
    int   width;
    int   height;
}

2. init — starting the clock

Runs once. Set the opening state, return a Cmd to do work.

pomodoro.c3
fn Cmd Model.init(&self) {
    self.phase     = Phase.FOCUS;
    self.remaining = phase_length(self.phase);
    self.running   = true;
    return milktea::every(1000);  // tick once a second
}

milktea has two timer commands, and the difference matters:

commandfiresuse for
tick(ms)ms after you call itanimations — you care about the gap between frames
every(ms)on the next wall-clock multiple of msclocks & countdowns — stays locked to real time
Timers are one-shot. They fire once; it's on you to re-arm them from update. That's what keeps the countdown going.

3. update — reacting to the world

Every event — resize, tick, keypress — arrives as a Msg.

pomodoro.c3
fn Cmd Model.update(&self, Msg msg) {
    switch (msg.kind) {
        case WINDOW_SIZE:
            self.width  = msg.window_size.width;
            self.height = msg.window_size.height;
            return null;

        case TICK:
            if (self.running && self.remaining > 0) {
                self.remaining--;
                if (self.remaining == 0) self.advance_phase();
            }
            return milktea::every(1000);  // re-arm

        case KEY:
            return self.handle_key(msg.key);

        default:
            return null;
    }
}
  • Window size arrives on startup and every resize — stash it, the view uses it.
  • The tick re-arms itself by returning every(1000) again.
  • Returning null means "done — wait for the next event."

Handling keys

Printable characters come in as KeyCode.RUNE with the character in k.rune; special keys have their own codes. Quit by returning milktea::quit().

pomodoro.c3
switch (k.code) {
    case CTRL_C:
    case ESC:  return milktea::quit();
    case TAB:  self.toggle_phase();
    case RUNE:
        switch (k.rune) {
            case 'q': return milktea::quit();
            case ' ': self.running = !self.running;
            case 'r': self.remaining = phase_length(self.phase);
            default:
        }
    default:
}

4. view — drawing the screen

Where layout and styling come together. Runs after every update.

Solve the layout with constraints

This is the heart of it. Instead of computing positions by hand, hand xray::layout a list of constraints and it fills in a Rect for each slot. First three horizontal bands:

pomodoro.c3
xray::Rect title_r, body_r, status_r;
layout::vstack(layout::screen(w, h), {
    layout::slot(layout::len(1),  &title_r),
    layout::slot(layout::fill(1), &body_r),
    layout::slot(layout::len(1),  &status_r),
});

// then split the body into a sidebar + timer panel
xray::Rect side_r, timer_r;
layout::hstack(body_r, {
    layout::slot(layout::len(22), &side_r),
    layout::slot(layout::fill(1), &timer_r),
});
constraintmeaning
len(n)exactly n cells
fill(w)share leftover space, weighted by w
percent(p)p% of available space
min(n) / max(n)clamp to a bound

Because everything is solved against w and h, the UI reflows on resize — no manual math.

Style with values

Styles are plain values you build, chain, and reuse. The accent color follows the phase — peach for focus, mint for breaks.

pomodoro.c3
glaze::Style timer_s = glaze::style()
    .foreground(accent).bold(true)
    .border(glaze::rounded_border()).border_fg(accent)
    .padding(1, 2, 1, 2)
    .align(glaze::Position.CENTER, glaze::Position.CENTER);

A free progress bar

glaze ships a progress bar — feed it a width, a percentage, fill/empty glyphs, and two colors:

pomodoro.c3
int pct = 100 - (self.remaining * 100 / total);
String bar = glaze::progress_bar(28, pct, "█", "░", accent, dim);

Render into rects, then stack

The bridge between geometry and styling: rect.render(style, content) sizes a styled block to fill its slot. Then glue everything with join_horizontal / join_vertical, which understand strings that already carry ANSI codes.

pomodoro.c3
String title_v = title_r.render(title_s, " 🍵 milktea pomodoro");
String side_v  = side_r.render(side_s,   side);
String timer_v = timer_r.render(timer_s, clock);

String body = glaze::join_horizontal(side_v, timer_v, 0);
String doc  = glaze::join_vertical(LEFT, title_v, body);
doc = glaze::join_vertical(LEFT, doc, status_v);

return milktea::new_alt_screen_view(doc);
new_alt_screen_view uses the terminal's alternate screen — the full-window mode vim and less use — and hides the cursor. For a simple scrolling tool, use new_view instead.

5. main

Wire it up and run.

pomodoro.c3
fn int main() {
    Model m = { };
    milktea::@run(&m);
    return 0;
}

That's the whole program — one struct and four functions. @run runs the loop and restores the terminal on exit.
