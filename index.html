A small, opinionated terminal UI library for the C3 programming language. Built on the Elm Architecture: your program is a model, an update, and a view. milktea owns the loop — you own the data.

what is this

milktea is a TUI framework. You describe your application state as a plain struct. You write one function that reacts to messages. You write another function that turns the state into text. The library drives the terminal: raw mode, the alternate screen, input events, resize signals, timers, and the render loop. You never touch ioctl, never manage a back buffer, never write an escape sequence by hand.

It ships with two companions: glaze builds styled strings (colors, bold, borders, padding) by emitting ANSI codes; xray is a cell-grid screen buffer plus a constraint solver for laying out panels. Three modules, three jobs, no overlap.

a program, whole

A complete milktea app — the canonical counter — fits in one screen:

      
●●●  counter.c380×24

      
module counter;

import milktea;
import glaze;
import std::io;

struct Counter {
    int value;
}

// init: run once, kick off any background work
fn milktea::Cmd Counter.init(Counter* self) @dynamic {
    return null;
}

// update: react to messages, mutate the model
fn milktea::Cmd Counter.update(Counter* self, milktea::Msg msg) @dynamic {
    if (msg.kind != milktea::MsgKind.KEY) return null;
    switch (msg.key.code) {
        case milktea::KeyCode.UP:    self.value++;
        case milktea::KeyCode.DOWN:  self.value--;
        case milktea::KeyCode.RUNE:
            if (msg.key.rune == 'q') return milktea::quit();
        default:
    }
    return null;
}

// view: pure function from state to screen
fn milktea::View Counter.view(Counter* self) @dynamic {
    glaze::Style box = glaze::style()
        .foreground(glaze::color_hex("#00d7ff"))
        .bold(true)
        .padding(1, 3, 1, 3)
        .border(glaze::rounded_border());

    String body = string::tformat("Counter: %d\nUse ↑↓ to change, q to quit", self.value);
    return milktea::new_view(box.render(body));
}

fn int main() {
    Counter c = { };
    return milktea::@run(&c);
}

That's the whole app. init seeds state, update folds messages over it, view renders it. No event loop, no redraw logic, no terminal juggling — milktea does all of it.

the three modules

milktea is a small family. Each module has exactly one job, and they compose without coupling.

milktea
runtime · event loop

Owns the terminal, raw mode, the alternate screen, and the message pump. Drives init → update → view forever.

░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
glaze
styling · ANSI

Builds styled strings: foreground, background, bold, italic, borders, padding, alignment. Just a value you call .render() on.

▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒
xray
layout · cell grid

A constraint solver for splitting a Rect into panels, plus a persistent cell grid for precise x, y drawing when you need it.

A simple app needs only milktea + glaze. Reach for xray when your layout outgrows a single box.

what you get for free

  • The Elm Architecture — state, update, view. Predictable, testable.
  • Truecolor (24-bit), 256-color, and ANSI palette support via glaze.
  • Keyboard, mouse, window-resize, and timer messages out of the box.
  • tick(ms) for frame pacing, every(ms) locked to wall-clock boundaries.
  • Rounded, thick, double, and normal border presets.
  • A constraint solver: len, fill, percent, min, max.
  • A cell-grid ScreenBuffer for pixel-precise placement and overlays.
  • TRANSPARENT compositing for layering popovers, menus, and toasts.
  • An alternate-screen renderer with per-frame diffing — no flicker.
  • A component library, boba: lists, tables, spinners, text inputs, toasts, timers.

layout that scales

Real apps have panels. xray::layout splits a rectangle into slots by solving a list of constraints — fixed lengths, weighted fills, percentages, min/max bounds. You render into each slot; milktea stacks them into one screen.

The same constraint vocabulary works vertically (vstack) and horizontally (hstack), with optional gaps. Layout is pure geometry — it doesn't know about styling, and styling doesn't know about geometry. milktea bridges them.

getting started

milktea is a C3 library. Drop the milktea/, glaze/, xray/, and boba/ folders into your project and add them to sources in your project.json. 

// project.json — minimal target
"examples/counter": {
  "type": "executable",
  "sources": ["milktea/**", "glaze/**", "examples/counter/**"],
  "c-sources": ["milktea/tty_winsize.c"],
  "opt": "Os",
  "strip-unused": true
}

Then build and run:

$ c3c build examples/counter
$ ./build_counter

philosophy

State is a struct. No observables, no signals, no reactive graph. You read it, you write it, you pass a pointer to update.

Views are pure. A view is a function of the model and nothing else. The same model always produces the same screen.

Small surface, sharp edges. Three modules, each with one job. No god objects, no framework magic, no hidden global state.

Terminal first. Built for people who live in $TERM. Fast, flicker-free, and honest about being text on a grid.
